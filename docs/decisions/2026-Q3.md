### Base decision — retire the mirror, ship docs + examples + resources (reconstructed)

- **Answer:** `jarvis-oss` stops being a squashed downstream mirror of `jarvis`; it becomes a
  docs + examples + resources repo with a setup skill.
- **Why:** value is ~10 decisions, not ~600 files; a clone inherits the author's shape of work;
  both sides pay sync rent forever.
- **Alternatives:** 1-on-1 advice / chat channel (agents read repos, not scrollback); keep the
  template (rent both sides); archive snapshot (argued from "zero operators", false); delete
  (irreversible, destroys the material).
- **Reversibility:** hard. **Confidence:** 0.8.
- *Provenance:* the design doc cites a journal entry for this decision; none was found in any
  `decisions.md` or `docs/decisions/` shard. Entry reconstructed from the doc's own text on
  2026-09-12 during the grill.

### D20 — Trust goes to the information, not the author: boundary clauses are evidence, the author only reviews (amends D15, reshapes the doc template)

- **Answer:** the author does not write the boundary clause; agents draft it from evidence
  already in the repos (decision-journal entries with their rejected alternatives, research
  artifacts, incidents, observed outcomes), and the author signs only as a human reviewer.
  The doc shape becomes: problem → options tried, each with why it was dropped → what settled
  → **when this applies** / **when it does not**, roughly half and half, each bullet pointing at

  presents several viable options; never as the focus.
- **Why:** user (2026-09-14): the goal is earned trust in the information, not in the author;
  an author-written boundary is an opinion, which is exactly what the reader should not be
  asked to trust. Readers need to know when to apply something at least as much as when not.
- **Alternatives:** author writes the boundary clause (D15 form — rejected: opinion as the
  trust anchor); ship agent drafts without review (rejected: hallucinated boundaries);
  "when not" only (the draft's form — rejected: readers first need the positive case).
- **Reversibility:** reversible. **Confidence:** 0.75. Open (round 5): whether the CI test
  also requires at least one evidence pointer inside the boundary section.

### D26 — `signed_off` provenance: the check must assume the agent commits from the author's account (refines D15, D18)

- **Answer:** a commit-author check cannot distinguish the author from an agent acting under
  the author's account. Sign-off is therefore recorded as a dated `signed_off:` frontmatter
  value plus a matching entry in a sign-off ledger (`docs/SIGNOFF.md` in jarvis-oss) that the
  author edits by hand in a separate commit from the doc change; the structure test fails a doc
  whose `signed_off` date has no ledger entry, or whose ledger entry landed in the same commit
  as a change to the doc body. Sign-off has a floor (the doc body has not changed since the
  date) and an expiry: a body change after the date clears the sign-off.
- **Why:** user (2026-09-15): the agent writes from the author's account, so provenance has to
  be designed with that in mind. The ledger-in-separate-commit rule is the cheapest thing that
  makes "an agent set `signed_off`" visible in review.
- **Alternatives:** GPG-signed commits (rejected: the agent uses the same key); trust the field
  (rejected: D20 says the field is the trust anchor).
- **Reversibility:** reversible. **Confidence:** 0.7.

## 2026-09-16 — The jarvis-oss content unit is a practice area, not a triple (amends AC items 4, 7, 8)

- **Answer:** a practice layer ships a **practice area**: one or more docs, one or more
  examples, one or more resources, however many each subject actually needs. The "exactly one
  doc + one example + one resource" triple that jarvis-oss #38 and its eleven children are
  written around is retired as a shape requirement — it was a convenient default that became a
  quota. Four things replace it, and all four are gated, not merely encouraged:
  1. **Coverage, not arity.** Every doc resolves to at least one example and at least one
     resource; every example and resource names the doc(s) it serves. Examples gain the
     `pairs_with` key resources already carry; both accept more than one target. The gate
     checks the graph, not the count.
  2. **Docs cross-reference.** Practice areas overlap — a review gate is also a merge gate is
     also a sign-off story — and the honest representation of that is a link, not a paragraph
     duplicated into two docs with drift between them. Relative links between docs are
     first-class; the existing link-resolution check already fails a dead one. Where two docs
     genuinely need the same fact, one owns it and the other links.
  3. **References carry provenance and may come from anywhere.** Three classes, each with its
     own frontmatter shape: the author's own projects (`last_seen:`, already defined),
     third-party projects (`source:` + `verified:`, already defined), and **research with
     data** — a study, a benchmark, a dataset — which gets `source:` + `verified:` plus the
     claim it supports stated in one line, because a citation whose claim is left implicit is
     decoration. An example drawn from another of the author's repos is an own example; one
     drawn from a stranger's repo is external; neither is more legitimate than the other and
     neither is a default.
  4. **Docs are written for the reader's repo, not for jarvis-oss.** `applies_when` /
     `applies_when_not` name a situation a reader recognises in their own project. Evidence may
     and should be specific to whatever repo it came from — that is what makes it evidence —
     but the *condition for applying the practice* may not be. AC item 4's doc shape is
     otherwise unchanged.
- **Why:** principal, on reviewing the first shipped area (jarvis-oss #41 / PR #50): the doc's
  `applies_when` read "publishing agent-drafted docs/examples/resources that must clear a human
  review point before shipping" and `applies_when_not` "internal process notes that are never
  meant to leave draft status" — both describing jarvis-oss's own publishing pipeline, so a
  reader arriving with a Django app and two collaborators cannot tell whether the practice is
  theirs. "Должно быть абстрактно достаточно, чтобы пользователь мог применить это к своему
  проекту." On the shape: "может быть не ровно triple, примеров может быть больше, чем 1,
  ресурсов может быть больше, чем 1, доков может быть тоже больше чем 1… могут быть пересечения
  между доками, возможно придётся делать кросс-референсы." And the verdict on the output the
  quota produced: "халтурно получается пока что, надо серьёзней к этому подойти." The failure
  mode is specific and worth naming: a fixed arity makes the second useful example a formatting
  problem and the third a violation, so the agent drafting under it pads the thin slots and
  truncates the full ones. Both directions of that pressure produce exactly the sloppiness
  observed, and neither is visible in a gate that only counts files.
- **Alternatives:**
  - *Keep the strict triple; split an over-full area into two triples* — rejected: it makes the
    directory shape decide the subject boundary rather than the other way round, and produces
    exactly the artificial doc-splitting the cross-reference requirement above exists to
    absorb.
  - *Allow N of each, with no linkage requirement* — rejected: without `pairs_with` on examples
    and a coverage check, "N" silently permits a doc with zero examples, which is the failure
    the triple was protecting against in the first place. Dropping the quota is only safe
    because the graph check replaces what it was standing in for.
  - *Free-form directories; let the reader navigate* — rejected: the whole differentiator of
    this repo over a blog is that every claim has a worked example and a runnable resource
    attached. That is a contract, and a contract needs a gate.
  - *Fix #41's doc wording only, leave the shape alone* — rejected: the wording and the shape
    are one finding. The doc was written to fill a slot, and the next eleven would have been
    too.
- **Consequence:** jarvis-oss #38 and its open children are rewritten off "triple" onto
  "practice area" before any further one is implemented; #41's already-shipped area is revisited
  under the new rules (its doc is currently unsigned — see jarvis-oss #52/#53 — so it has not
  shipped anything yet). The structure gate grows two checks: `pairs_with` on examples, and doc
  coverage (≥1 example, ≥1 resource per doc). AC items 7 and 8 are amended to the above; item 4
  gains the generality clause. Sequencing: this lands before jarvis-oss #53's review hold is
  built, but no content PR merges until #53 exists — the two are independent fixes to the same
  PR #50 post-mortem, one about what gets written and one about who is allowed to bless it.
- **Reversibility:** reversible — no content has shipped signed yet, so the rewrite cost is
  eleven issue bodies and two gate checks, not a published repo's structure.
- **Confidence:** 0.8.

## 2026-09-21 — jarvis-oss: a calibrated agent review replaces the per-document human sign-off (supersedes D15, D20, D26; amends D1, D11, D17, D18, D19, AC items 1, 3, 5 and the `v0.9.0` binding)

Record of the `/grill` session (2026-09-19 – 2026-09-21), committed with personal literals
scrubbed: [`grill/2026-09-21-agent-review/`](grill/2026-09-21-agent-review/). Raw critique file
(117 verdict IDs: sampling critic, coverage critic, grounding pass):
[`critique-raw.md`](grill/2026-09-21-agent-review/critique-raw.md). Beside it: `payload.md` (what
the critics saw, i.e. the design as drafted), `triage.md`, `dispositions.md` (one answer per
decision cluster) and `design-final.md` (the locked design with AC1–AC17). Research artifact:
[`agent-reviews-agent-2026-09-19.md`](../research/agent-reviews-agent-2026-09-19.md). The triage
files number their decision clusters D1–D25; those are not this journal's D-entries. Below,
"D15" always means this journal and "cluster 4" means the triage file.

- **Answer:** the per-document human signature is removed. A doc in jarvis-oss is published on a
  same-model, fresh-context agent review that runs in GitHub Actions as a required check, plus
  the deterministic checks, plus a small amount of named human work. The human's per-document
  work does **not** go to zero, and nothing may say it does.
  1. **What the human still does.** (a) A click-audit: per doc or release, k randomly drawn
     claims of the blocking classes are click-checked against their source; a miss goes to the
     corpus. (b) A leak read of every scrubbed trace in `examples/` and of any PR that adds
     private-derived material. (c) Every PR that touches the reviewer's own machinery: the
     review workflow, the skills, the calibration files, the gates. (d) The merge of content
     PRs. (e) A `/doc-loop` stop after round 3.
  2. **What the review aims at.** A dated, as-of-review aim, not a promise: for each in-scope
     reader type a doc does not lead to an option that (i) is unavailable on that reader's plan,
     (ii) contradicts a quoted source, or (iii) leaves the reader with no next step. A finding is
     `blocking` iff it breaks (i)–(iii), or is a claim-check `mismatch`, or is a wrong
     `tried`/`sourced` status. Everything else is a follow-up issue. Wrong non-blocking facts may
     ship, and the README says so.
  3. **Scope.** Four reader types: solo or a team of at most three, each with or without money.
     The attended/unattended-agent axis is asked wherever it changes the answer. Examples are
     GitHub-only. `tried` is claimed only for the author's own reader type (solo, GitHub Free,
     paid AI subscription); on a public source project it links the public commit, PR or run, on
     a private one it keeps a scrubbed trace in `examples/` and the README says it is
     self-reported. Existing docs move to this scope one at a time, as each passes `/doc-loop`.
  4. **Trust basis.** The reviewer is the same model as the writer in a fresh context; no
     independence is claimed for it. The calibration corpus holds real escaped defects; the label
     rules and the held-out rule are committed before any corpus result is read. There is **no
     numeric gate**. What is published is counts only (caught / missed / n, per class, with the
     spread over k=3 calibration runs), labelled "a floor on same-model agreement", not recall,
     until a defect source the model did not select (the click-audit, reader reports) has data.
     A drift key (workflow file, pinned action version, explicit `--model`, `SKILL.md` hash)
     is stored with the calibration; a mismatch fails the review check. A silent vendor update
     under the same model id is not detected, and that is disclosed.
  5. **Enforcement.** The review job always runs on `pull_request` from same-repo branches,
     classifies the PR itself, passes non-doc PRs explicitly and fails unreviewable ones and
     drafts explicitly; red or pending means wait, never a human-hold fallback. A second required
     check runs on `pull_request_target` with no checkout, reads only the changed-file list, and
     fails any PR that touches reviewer machinery. `check_quotes.py` becomes a required check
     (fails on `NOT FOUND` only) and the full `tests/` suite runs in CI. The record is one flat
     frontmatter key, `review: <PR URL>`, which may be empty; the report is a PR comment; the
     counts live in the README only. `signed_off`, `docs/SIGNOFF.md` and the two-commit rule go.
  6. **"The human merges" is a convention with a detector, not a mechanism.** The agent works
     under the human's account and token. A harness deny hook blocks `gh pr merge`, removal of
     `waiting-human-review` and the branch-protection API; that is a hold, not proof. A detector
     workflow on `branch_protection_rule` and `pull_request: unlabeled` opens an issue on every
     such event. The `waiting-human-review` check stays required permanently; only its
     auto-application is removed, once the click-audit finds zero misses on two consecutive docs
     the human chose.
  7. **Process.** `/doc-loop`: write, self-check, review in Actions, fix under the write-doc fix
     protocol, delta review, report. At most three rounds, counted by the workflow, not by the
     agent; the stop message reports observed facts (open blocking findings per round, share of
     fix-induced findings). One rolling follow-up issue per doc. A weekly `check_quotes` cron,
     enabled only after a baseline run.
- **Why:** principal: "Я не эксперт и мой sign off ничего больше не подтверждает"; "Мой sign-off
  сужается до … 0. Всё, что знаю я, знает и агент, всё, что я делал записано." D15 rested on the
  boundary clause existing "nowhere but in the author's head"; D20 already moved that clause to
  evidence in the repos, which left the signature certifying only that a human had read the doc.
  On PRs #75 and #81 that read did not catch the defect classes that matter (wrong plan-tier
  facts, misquoted sources, options that do not fit the reader); later review rounds did. A
  signature that certifies a check nobody performed is worse than no signature, because the
  reader takes it as one. On what the docs owe a reader: "'Для какого читателя документ
  гарантирует ответ' - ни для какого. Для выбранных типов читателей мы гарантируем предоставить
  информацию для обучения, мощную стартовую точку." The principal's own direction was "sign-off
  → 0"; the critics showed that four pieces of human work remain that no agent step replaces
  (items 1a–1d), so the entry records the narrower result rather than the one asked for. The
  research supports calibrating on real escaped defects (synthetic defects overstate a reviewer
  by up to an order of magnitude), and does not support a second vendor as a source of
  independence (nine judges from seven families behave like about two independent votes).
- **Alternatives:**
  - *Keep D15/D20/D26 as they are* — rejected: the signature's one remaining meaning ("a human
    read this and would have caught it") is contradicted by two PRs of evidence and by the
    signer's own statement.
  - *The human signs the calibration result instead of each doc* (the design as drafted) —
    rejected: the same unverifiable signature one level up. Replaced by the click-audit, which
    is clerical and needs no expertise: open the link, compare the quote.
  - *A numeric recall gate* (point recall ≥ 0.8 at n ≥ 30, then the lower bound of a 95%
    interval ≥ X) — rejected: n is too small to carry a threshold, and a corpus whose defects
    were found by the same model measures agreement with itself, not recall. Counts only, until
    a model-independent source has data.
  - *A reviewer from another vendor, or an ensemble* — rejected: the research found near-zero
    added independence, and it adds a second credential and a second drift axis.
  - *Claim independence from the deterministic checks* — withdrawn: `check_quotes`, the
    structure gate and gitleaks do not cover the blocking classes (i) and (iii), so the claim
    would be true of the checks and false of the guarantee.
  - *A separate agent identity (machine user or GitHub App), making "the human merges" a
    mechanism* — not taken now. Principal: "отдельную учётку для агента не получится сделать." A
    GitHub App is recorded as the known upgrade; return condition: the detector fires once on an act
    the human did not perform.
  - *Keep auto-applying the PR hold forever* — rejected: the agent can remove the label with the
    same token, so the hold never protected against the agent; it only reminds the human.
  - *A human-hold fallback when the review check is red or out of quota* — rejected. Principal:
    "квоты хватит". A fallback path is a fail-open path.
  - *Frontmatter `reviewed: {commit, report, recall}` plus a review ledger with the two-commit
    rule* — rejected: a doc cannot name the commit that contains it, and a recall figure copied
    into every doc goes stale on the next calibration.
  - *Run the review on `pull_request_target`* — rejected: public repo; checking out PR code
    beside the OAuth token is the documented way to lose the token.
- **Consequence:** what each touched entry now means.
  - **D15, D20 (its "the author signs only as a human reviewer" half), D26** — superseded. D20's
    evidence rule stands; this entry does not touch its doc shape.
  - **D1** — the audience is still anyone who arrives; the aim in item 2 is scoped to the four
    reader types, and a reader outside them is told the doc is a starting point to adapt.
  - **D11** — trust is still not gated on a metric. Counts are published, with their label, so
    that a reader can weigh the claim "checked by automation".
  - **D17, D19** — Issues also accept doc errors through one `doc-error` template (doc, quote or
    line, what is wrong, source link). The agent triages; an entry reaches the corpus only after
    the human's click-check. Discussions stay the place for questions; still no turnaround
    promise.
  - **D18, AC item 3** — the docs' required key `signed_off` becomes `review` (a PR URL or
    empty); the ledger and same-commit clauses are removed; the rest of the structure gate is
    unchanged.
  - **AC item 1** — `main` additionally holds the review, machinery-guard, detector and cron
    workflows, the `review-doc` / `write-doc` / `doc-loop` skills, the calibration corpus and
    `CALIBRATION.md`, the scripts and tests those need, and one `ISSUE_TEMPLATE`.
    `docs/SIGNOFF.md` leaves.
  - **AC item 5 and the `v0.9.0` entry** — item 5 still binds to the first public release, but
    now reads: at `v0.9.0` the README lists every shipped doc with whether it passed the
    calibrated review and when; a doc that has not passed carries an empty `review:` key and is
