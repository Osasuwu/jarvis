# Sampling critic — raw verdict (verbatim; IDs added by operator)

## Risks

### S1
- [HIGH] The pull request under review controls the required check. On `pull_request`, the workflow file, `review-doc/SKILL.md`, `CALIBRATION.md` and `tests/structure_gate.py` are all read from the PR's merge commit. A same-repo agent PR (for example a `/doc-loop` fix round) can change the reviewer and the calibration record in the same diff, which makes the AC12 hash comparison meaningless, or turn the job into a no-op under the same check name. This needs no admin action, so the "admin-token residual gap" in point 6 does not cover it. The reviewer also runs web fetch and Bash with the OAuth token in its environment, so content from fetched pages can influence the verdict. — `docs/private-literal-scrub.md:145` ("the workflow file comes from the merge commit… can edit the step to pass"); `.github/workflows/structure-gate.yml` (same pattern); `gh api …/branches/main/protection` (required checks are matched by context name + app_id only); claude-code-action `docs/security.md`.

### S2
- [HIGH] The recall figure is biased upward, and the gate is probably not reachable as drafted.
  - **Biased denominator.** "Escaped" means the same reviewer found the defect in a later round. Defects no run ever finds are left out of the denominator.
  - **Low single-run catch rate.** The repo's own data shows this on real defects: "Five real defects… seen in a single run only", "agreed on none of the extra findings".
  - **n refers to different things.** AC2 asks for ≥30 entries of any severity; AC3 gates on blocking recall without setting an n for it.
  - **Few blocking defects are available.** #75's own takeaway is that most rounds went on fix-introduced defects, which the "escaped" definition excludes. Most findings were "wording a signer can live with".
  - **Labels are retrofitted.** The #75 reports predate severity labels, so blocking/follow-up would be assigned afterwards by the agent, under a definition no run has used.
  - **The numbers.** Wilson 95% lower bound: 15/15 = 0.796, 30/30 = 0.886, 29/30 = 0.833, 28/30 = 0.787. X = 0.8 at n = 30 therefore allows at most one miss.
  — `.agents/skills/review-doc/CALIBRATION.md:74,157-159,174-176,277`; PR #75 comment 2026-09-18T07:06 ("most of the rounds were spent on defects the fixes themselves introduced"); the held-out rule also bites, because skill change #87/#89 was driven by #75/#81 (`CALIBRATION.md:172-176`).

### S3
- [HIGH] The negative guarantee narrows what counts as must-fix, and the writer agent can satisfy it cheaply.
  - **What drops to follow-up.** Today every `mismatch` is must-fix, including numbers, tool behaviour and `tried` without a trace, along with every `missing` option and the value test. Under "contradicts a *quoted* source… everything else is a follow-up", unquoted wrong facts and `unverifiable` claims become follow-ups.
  - **Clause (iii) has a boilerplate escape.** "Apply the principle; look for the analogue" satisfies it.
  - **The incentive this creates.** A writer-and-fixer agent under a 3-round cap is rewarded for quoting less and appending the fallback line. Blocking recall rises while the guaranteed content shrinks.
  — `.agents/skills/review-doc/SKILL.md:34-50,182-185` versus payload point 2; Run 1 plants E2/E3/E6 (number and tool-behaviour errors) would not clearly be `blocking` under the new wording (`CALIBRATION.md` Run 1 table).

## Unmentioned alternatives

### S4
- Run the gate from the base branch.
  - **What.** A `pull_request_target` job, guarded to same-repo heads, takes the workflow, skill and calibration record from `main` and reads the PR's docs as data only, never executing them.
  - **Why it may have been missed.** The proposal bans `pull_request_target` outright (AC4) instead of banning only the form that checks out and runs PR code. The repo's own doc names this as the one route left on a personal account (`docs/doc-structure-gate.md:280-292`, `docs/private-literal-scrub.md:140-149`).
  - **Trade-off.** Secrets sit next to PR-authored text. The reviewer's tools would need an allowlist, and skill changes take effect only after they merge.

### S5
- Review with the union of k fresh runs per pass, calibrate the union, and use run overlap to estimate what nobody found.
  - **What.** The run-overlap method is capture–recapture (Briand, El Emam, Freimut, Laitenberger, IEEE TSE 26(6), 2000, "A comprehensive evaluation of capture-recapture models for estimating software defect content").
  - **Why it may have been missed.** The design fixes a single reviewer and only measures it, even though `CALIBRATION.md:74,157-159` shows run-to-run variance is the main way defects escape.
  - **Trade-off.** It costs k times the tokens on a subscription quota shared with interactive work, and same-model runs are correlated, so the estimate is still a lower bound. It is, though, the one estimator here that reaches defects no run found.

### S6
- Replace the per-document signature with a random-sample clerical audit by the human.
  - **What.** For each doc or release, the human checks k randomly drawn `blocking`-class claims. Each check is a click-through: is the quote on the page, is the plan-tier line on the pricing page. Misses are logged in the corpus.
  - **Why it may have been missed.** "I am not an expert" was taken to mean "zero verification value". Clauses (i) and (ii) need a browser, not domain expertise.
  - **Trade-off.** It costs minutes per doc. It would be the only ground truth in the design not produced by the model, and it gives an escaped-defect rate that does not depend on the same-model corpus.

## Challenged assumption

### S7
- The proposal assumes independence comes from the deterministic checks, and that same-model recall is therefore a sufficient basis for the README line "the information is verified and can be trusted". Here is what those checks actually cover:
  - `check_quotes.py` verifies wording only: "not whether the doc's claim around the quote matches the source; that stays review-doc's job" (`scripts/check_quotes.py:22-23`).
  - The structure gate checks shape.
  - gitleaks checks secrets.
- So clause (i) plan availability, clause (iii) next step, and the claim-versus-quote half of clause (ii) have no independent verifier. For these, the sole checker is the writer's model, which the skill itself says "can share blind spots" (`.agents/skills/review-doc/SKILL.md:196`). It is scored against a corpus whose entries and blocking labels the same model produced.
- The human signing `CALIBRATION.md` moves the signature the human called worthless up one level. They cannot audit the corpus labels any more than they could audit the docs.
- The published recall number would measure how consistently the model agrees with its own later runs. It would not measure the defect classes the problem statement says matter.

- **A1** · **Assumption 1**: Recall measured on "escaped" defects from #75 and #81 estimates the reviewer's recall on blocking defects in future docs.

### Premortem

**P1** · **Failure narrative**: The corpus never reached 30 held-in blocking defects under the narrowed definition. The gate was then either set from a small, relabelled, same-model-selected sample or left provisional, and the README published a recall figure that readers took as "share of errors caught". Meanwhile docs shipped with wrong unquoted facts that had been classified as follow-ups, and the follow-up issues piled up unworked in a tracker nobody triaged. The 3-round cap sent most docs to the human anyway, so the manual load did not drop. At the same time, a reviewer-editing PR or an agent-performed merge showed that the required check was self-administered. An obviously wrong published doc, or a leaked private string in a scrubbed trace that no human had read, made the README's trust claim untenable, and the per-doc human read was restored.

**Earliest preventive decision point**: Design point 2 together with the first bullets of design point 5. This means the definition of `blocking` and the choice of what the recall figure is measured against (same-model "escaped" defects, labelled by the agent, with X set afterwards). These were fixed before the enforcement and README work began.
