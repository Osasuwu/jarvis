## Challenged assumption
- [S7] That a green `risk-tier` on the admin's own HIGH PRs is a precondition for making the check required (the proposal's "Then `risk-tier` can be made required"). On this repo `enforce_admins` is false by decision (D12) and by measurement (G23), so a required red check never blocks the admin; it blocks the bot and other write collaborators, which is the population D10 scoped the hold to in the first place. What the green actually buys is that an agent session acting as `Osasuwu` no longer has to pass `--admin` and the hook's marker — the exact path D12 chose to keep closed. The proposal therefore reverses D12 while listing only D10 as the decision it corrects, and its doc change files the consequence as a new residual ("an agent session acting as the admin is not held by this check") rather than as the reopening of a closed one; the deferred items (narrowing the protected-path list) are the lever that would shrink the red-on-admin count without touching who the hold binds. — `docs/decisions/2026-Q4.md:376-385,398-405`; `docs/decisions/grill/2026-10-06-afk-orchestration/raw-grounding.md:45`; `docs/decisions/grill/2026-10-06-afk-orchestration/triage.md:67-70`
