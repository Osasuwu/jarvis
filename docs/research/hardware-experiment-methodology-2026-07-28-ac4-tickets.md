## redrobot — `SergazyNarynov/redrobot`

### 1. Репетиция краснеет при нулевой различимости — AFK · **новый**

`main()` в `scripts/rehearse_robot_day.py` возвращает ненулевой код, а расписка строится красной, когда ни один эксперимент дня не различает ни одной пары засеянных гипотез. Сегодня такой прогон зелёный.

AC несёт негативный тест: репетиция на матрице, где все эксперименты дают одинаковый исход при всех гипотезах, обязана вернуть ≠0 и расписку, которую `verify_receipt` не принимает.

Почему первым: без него всё остальное — краска поверх краски.

### 2. Валидация строки «ни одна из ветвей» — AFK · **новый**

`MatrixRow.__post_init__` (или эквивалентная точка валидации матрицы) требует наличия строки-двойника «ни одна из ветвей» и падает без неё. `docs/ROBOT_DAY_RUNBOOK.md:23` уже утверждает, что она проверяется на репетиции — привести код в соответствие с документом.

Blocked by: —

### 3. `Step.repeats` + разброс в отчёте дня — AFK

Поле `repeats: int = 1`, раннер прогоняет шаг n раз, `StepResult` копит наблюдения, `format_day_report` печатает разброс. `__post_init__` требует `repeats > 1` для шагов с числовым вердиктом; признак «числовой вердикт» — **явное поле**, не эвристика (иначе AFK-вопрос 3 срабатывает).

**Ревизия:** AC обязан требовать, чтобы рядом с разбросом печаталась пометка «разброс — не оценка неопределённости, пока не заполнены строки типа B», и чтобы в отчёте было место под эти строки. Три повтора дают только u_A по GUM.

Blocked by: —

### 4. Записанное предсказание + surprise rate — AFK

Пометка ожидаемого исхода на строке матрицы, валидация «ровно одна строка помечена либо явный `unknown`», `format_day_report` печатает долю сюрпризов.

**Ревизия:** AC требует, чтобы `expected` сопровождался полем с **названным механизмом**, из которого предсказание выведено (пустое поле = `unknown`), и чтобы surprise rate печаталась **рядом с долей `unknown`**. Иначе получаем 100 % формального соблюдения при нулевой диагностичности (Szollosi).

Blocked by: **3** — по файлу: обе правки трогают `Step` и `format_day_report`.

### 5. Реестр осей неопределённости `AXES` как данные — **HITL** (вопросы 2 и 3)

Оси как данные + объявление шагом «варьирую / фиксирую» + печать непокрытых мест на `--dry-run`. Механика тривиальна; **список осей — доменный вызов из истории err221** (J4, скорость, инструмент, направление, нагрузка). Свежая сессия по одному AC выберет оси наугад.

Метка: `unsafe-for-afk`.

Печатать пары осей, не покрытые ни одним экспериментом дня, и ячейки без негативного двойника; краснеть на непокрытых.

### 7. Секция «чего репетиция проверить не может» в отчёте — AFK

Фраза из докстринга `rehearse_robot_day.py` переезжает в вывод, рядом с зелёной таблицей. Формулировка «мок по построению не содержит сюрпризов, которых мы не вообразили» ревизию выдержала — переносить дословно.

### 9. Claim ledger + отказ data-sufficiency guardian — **HITL** (вопрос 2)

Форма записи: гипотеза · оси · собранные ячейки (позитивные / негативные / неуверенные) · порог выборки · статус (`гипотеза` → `подтверждена на подмножестве` → `root cause`). Плюс засев первой записи по err221 и доопределение памяти `robot_measurement_data_sufficiency_role`: Jarvis **явно отказывается** формулировать вывод о поведении контроллера, пока не заполнены пункты 1–4 протокола §AC2, и называет это отказом.

**Ревизия:** статусы получают обязательную модальность глагола (GRADE): `гипотеза` → «может быть причиной», `подтверждена на подмножестве` → «вероятно, является причиной, проверено на N из M конфигураций», `root cause` → «является причиной»; переход в последний требует **двусторонней** проверки (отключили — исчезло, вернули — вернулось).
