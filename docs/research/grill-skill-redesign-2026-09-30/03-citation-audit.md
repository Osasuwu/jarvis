# /grill redesign — citation audit of `02-external-evidence.md`

Date: 2026-09-30. Auditor: independent agent, did not write the file under audit. File audited: `docs/research/grill-skill-redesign-2026-09-30/02-external-evidence.md` (324 lines). Nothing in that file was changed.

## Method

- Every cited URL was fetched by me, not taken from the author's notes: arXiv `abs/` and `html/` pages with curl; PDFs (STPA Handbook, CIA Tradecraft Primer) converted with `pdftotext`; Anthropic and Claude Code docs as `.md`; GitHub files via raw URLs and read-only `gh api` (file contents at pinned commits, commit patches, commit dates); local-repo statements checked against `skills/grill/` in this worktree.
- Quotations were checked by whitespace-squashed, typography-normalised substring match against the saved source text. A miss was then inspected by hand to separate markup differences (LaTeX, markdown links, table padding, two-column PDF layout, non-breaking hyphens) from real misses.
- Numbers were checked against the table or sentence they come from, including the condition (model, scenario, injected versus natural errors) and the direction.
- Firecrawl: 4 calls of the 15 allowed (ScienceDirect only; one call wasted on a mistyped PII that returned 404, one re-fetch of the HAZOP abstract). No `firecrawl_agent`. No reddit.com fetched.
- Verdict vocabulary: SUPPORTED / SUPPORTED-WITH-CAVEAT / QUOTE NOT FOUND / NUMBER MISREAD / OVERSTATED / WRONG SOURCE / UNVERIFIABLE.

## Coverage

- Atomic checkable claims extracted: about 255 — 165 quotations (37 in Part A, 128 in Part B) and about 90 non-quote claims (numbers, dates, commit hashes, line counts, locations in `skills/grill/`, paper ID ↔ title pairings, statements about current repository or documentation contents).
- The count is over 120, so rule 5 of the brief applied. Audited in full: all of Part A; every quotation and every number in Part B; every commit hash and date; every local-repo measurement; the comparison table; the 24 arXiv ID ↔ title pairings in Sources; every "What this implies" bullet that restates a source as if the source said it.
- Sampled rather than exhaustively audited: nothing among quotations and numbers. Among plain attributions, the ones not separately rowed below are those that only repeat an already-audited quotation.
- Not audited, and why: the eight "no evidence found" statements (lines 59, 60, 97, 117–119, 132, 297–306) are negative search results and cannot be checked by fetching a cited URL; the "Read" depth labels in Sources and the Firecrawl count on line 11 describe the author's process.
- The checks are grouped into the 115 rows below. Quotation result behind the rows: 165 checked, 164 present verbatim at the cited URL modulo markup and typography, 1 not at the cited URL (row 47).

## Defects, ordered by how much each would mislead a design decision

1. **Row 88 (L166) — which part of SKILL.md survives compaction.** The file says Phases 3–4 fall outside the 5,000-token window and recommends moving the lock-time procedure first or shrinking the body on that basis. By the file's own 4-characters-per-token estimate the cut lands at line 213, inside `<supporting-info>`; both phases are inside the window. Phase 4 is at risk only if real density is 3.8 bytes per token or lower, Phase 3 only below about 3.3. The recommendation may still be right, but it needs a real token count first; as written it is a conclusion the numbers in the same file do not give.
2. **Rows 5, 7, 56, 60 (L21, L39, L95, L102) — third-person persona on frontier models.** The file corrects the skill's "~64%" (correctly) and then replaces it with "about none on frontier models" and "one of three scenarios". Table 4 shows the closed models at ceiling in the debate scenario, so no gain is measurable there; in the unethical scenario the same prompt improves 10 of 11 models, all three closed ones included; in the false-presupposition scenario it lowers 9 of 11, not two. The honest summary is "unmeasurable in debate at ceiling, small gains in one other scenario, mostly small losses in the third", which does not support either "64% reduction" or "no effect". A decision to drop the framing as useless would rest on the overstated reading.
3. **Row 93 (L170) — "rule count matters more than line count".** Neither study measures line count. The supported statement is only that adherence falls as the number of discrete instructions rises. A rewrite that trades length for fewer rules, or the reverse, has no backing from these two papers.
4. **Rows 110, 108, 37 (L219, L211, L60) — prior-art convergence.** "Four independent designs" counts a fork and its parent as two; "a recommended answer on each" and "gated by dependency or materiality" are not true of superpowers; and the table says superpowers does not state code lookup when its checklist opens with "Explore project context — check files, docs, recent commits". The convergence argument is weaker than presented, and the one tool the table shows as not grounding in code does.
5. **Rows 47, 51 (L78, L85) — reviewer calibration.** The calibration wording is quoted from a file other than the cited one, and it is then listed as a "supported mitigation". The only thing the release notes report about the calibrated review loop is that it was removed for adding no measurable quality. Calibration is an untested practitioner choice.
6. **Rows 14, 49 (L24, L40, L83) — "the critic payload contradicts the paper it cites".** The payload-equals-SA mapping is the author's inference (flagged only in Gaps), and the paper's own wording is that the SA–SR difference "is not significant".
